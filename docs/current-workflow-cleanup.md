# 現在の操作経路を基準にした整理

2026年10月24日。本人から、現在の操作で使わないコードの削除とリファクタリングを依頼された。構成図・対話・期待・検証・結果・比較を現在の操作経路とし、固定環境の準備、医療OSSの実行、確認資料と履歴の管理も残す。

## 削除したもの

- 名前・年齢の型と入力検証、架空データのTCPクライアント・サーバー、人工故障、答え合わせ用のTruth、専用プロトコル。
- `demo`、`suite`、`verify`、`retest`、`show`、`compare`、`capture`、`review`、`explore`と、`case run`・`case export`の旧CLI。
- `/demo`・`/review`・`/explore`、そのJavaScript・CSS・HTML、LikeC4の固定見本と生成済みアセット。
- ブラウザ内の旧解析コード。現在のRust側の解析と保存済みテストデータは使う。
- VitalSensing専用の旧アダプターと判定、旧比較資料の作成、廃止した画面・デモだけを対象にしたテストとCI手順。
- 本体では呼ばずテストだけで使っていたlocal実行の省略関数。省略関数はテスト用の補助コードへ移し、本体からは実行方式を指定する。

## 分離した責務

`main.rs`はCLIの呼び出しとエラー表示だけにした。`cli/mod.rs`は起動・AI設定・API・リポジトリ準備、`cli/case.rs`はケース管理、`cli/environment.rs`は固定環境の操作を扱う。

初期デモのexperiment.rsにあった共通の試行情報と記録完了処理はrun_record.rsへ移した。新しい試行はデモのname/ageやTruthを生成しない。現在の入力・故障条件は既存のRecipe、独立した読み出しは実行トレースへ記録する。

現在のブラウザ画面はapp.html、app.js、repository-diagram.js、workbench.html、workbench.jsと共通CSSから成る。詳細設定は、デモとの選択画面を挟まず、対象のURLまたは構成図からの引き継ぎを開く。

## 既存の保存内容

既存の保存ファイルを削除する処理は追加していない。Manifestのinput/faultとEvidenceのadapterは、保存済みの情報を保つためにJSONとして読み出す。名前や年齢を基盤の入力条件として解釈しない。

旧規則名demo_save/local_index_uploadedと旧イベント名は、保存済み履歴の読取に必要な形式として保持する。旧規則の現在の判定はUnknownで、新規のケース・確認事項への指定や試行の取り込みは拒否する。保存した過去の判断と、現在の検証結果を区別する。合成の旧形式について、読み出し・バックアップ・復元と新規指定の拒否をテストする。

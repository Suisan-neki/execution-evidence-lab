# 番号表示の構成図と個別観測の検証

2026-10-18。#161。PR #160の共通モードと参照アプリに続く追加実装。

LikeC4 1.60.0で既存3対象と番号表示の全体図・内部構成を生成した。番号表示では、固定版の実コードを使う試行の結果を図から確認した。コードの版・構成の版・観測当時の結果・現在の条件への適用を分ける。

## 確認したこと

- fmt・check・clippyの警告をエラーにする確認が成功。
- Rust121件が成功。Docker等を使う4件は既存の指定どおり無視。
- 描く要素・接続・表示文・階層・環境が変わった構成には既存の配置を適用しないことをRustで確認した。
- 番号表示の誤表示→改修→正常→保存失敗→未観測→正常な再試験を実行した。図では一つの試行の個別観測を参照し、古い結果の適用範囲を区別した。
- 図から疑問と試験結果・証拠を開き、元の要素へ戻る操作が成功。
- 構成の表示名を変更した新しい版では、以前の図を表示せず未生成と示した。
- 既存の構成図の操作試験と、OpenEMR・OHIF・MONAIの見本の保存・切り替えが成功。
- Chrome Headless Shell 151.0.7922.34とPlaywright 1.62.1で1440px・390px・320pxを操作した。番号表示の画像を目視した。

## 何を同じものとして扱うか

図に描く構成と環境がすべて一致した場合だけ生成済みの配置を使う。コードのコミットが変わったことだけを理由に図を捨てず、保存した構成モデルと試行の参照を保持する。構成図の線を、その版のコードが実際に通信した証拠として扱わない。

保存先の異常を入れた試行と、正常な最新試行は実行条件が異なる。以前の故障試行に失敗の観測があっても、現在の条件への適用は別に確認する。図では再確認の必要性と観測当時の失敗を併記する。未観測の読み出しを過去の成功で埋めない。

## 再現と限界

```bash
npm ci --ignore-scripts
npm run build:architecture
cargo build --locked
npx playwright install --with-deps chromium
npm run test:queue-architecture
npm run test:architecture
npm run test:architecture-targets -- presets
```

`test:queue-architecture`は信頼できる参照コードをlocal方式で実行する。外部通信の網羅的観測、OSの隔離、本番環境、医療機関の要件、実参加者の理解は確認していない。任意の構成をコードから自動抽出・生成する機能は未実装。

画像は`test-results/queue-architecture-1440.png`・`queue-architecture-390.png`・`queue-architecture-320.png`へ保存する。CIには同じ操作試験を追加した。CIの完了はPRの対象コミットで確認する。

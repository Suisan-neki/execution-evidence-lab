# リポジトリから全体の構成を読む

公開GitHubの固定コミットを読み、画面、要求を処理するアプリ、保存先、接続するサービスを1枚の図へまとめる。非技術者と技術者は同じ要素・接続・配置を参照し、説明の詳しさを切り替える。

## 図と説明

非技術者向けには、各部分の役割と情報の流れを示す。技術者向けには、同じ部分の技術名、起動イメージ・ポート、APIの入口、保存処理や接続の記述を追加する。内部の処理は選んだ部分の説明へまとめ、ファイルを一つずつ全体図へ並べない。

箱と接続線はキーボードでも選べる。説明の根拠から固定コミットの設定・コードへ戻れる。不安や疑問は、選んだ要素・接続、または全体に記録する。疑問を保存した時点では、期待する動作や検証結果を作らない。

検証したい動作を記入すると、既存の詳細設定へ進める。検証画面から戻ると、元の要素や接続を選択する。保存済みの疑問からも同じ部分を選べる。図の読み取り範囲や説明が変わった場合、その変更を疑問の記録に表示する。元の出所を別の要素へ自動で付け替えない。

## 箱と線の根拠

| 読み取るもの | 図への対応 | 判断しないこと |
| --- | --- | --- |
| Composeのservices・image・build・command | サービスと実装のまとまり、起動方法 | 起動済みか、配備先と一致するか |
| 環境変数に明示されたサービスURL | 指定された接続先と接続方法 | 接続や保存に成功したか |
| depends_on | 点線の「起動を待つ」 | データをやり取りしているか |
| UI・APIの生成、HTTP要求、保存・SDKの呼び出し | アプリの役割、保存先、接続の推定 | 必ず実行されるか、業務上正しいか |
| 認証サービスのURL設定 | 点線の「認証先の設定」 | 実際に通信・認証できるか |
| 説明資料で特定のディレクトリを旧構成・試作と明記した項目 | 「別の構成・試作」のまとまりと出所 | 実際の稼働状態 |

依存パッケージの一覧、import、コメントに書いた例だけから、稼働する外部サービスを作らない。ファイル間の参照宣言を通信へ読み替えない。構成を特定できない場合は不足を説明する。

## 実装

読取と抽出はRustで行い、対象コードを起動しない。最初の24ファイルに加え、構成の要求時に説明・設定・起動や接続のコードを最大48ファイル補う。設定を優先し、本文は各128KiB、補完時の合計見積りは6MiB以内とする。未読と、役割を特定できなかったコードを区別する。

`src/reader/repository_map.rs`でサービスと責務を共通の識別子へまとめ、Composeとコードの読取は別モジュールに分けた。生成する要素・親子関係・接続・根拠は、既存の`src/architecture.rs`の型と検査を共用する。古い見本の選択画面は入口へ戻さない。

構成要素の識別子は、サービス定義や実装のまとまりから作る。図の説明・根拠・接続を含む内容の識別情報を`model_revision`として返し、疑問の出所へ保存する。この値は実行や安全性の判定ではない。ファイルの移動やコミットの更新後も同じ役割を指せることを、架空の事例で確認する。

配置にはELK 0.12.0を同梱する。外部の図作成サービスへモデルを送らず、実行時のNode.jsやCDNも使わない。`npm ci --ignore-scripts`後に`npm run build:repository-layout`で同じ配布ファイルを再生成できる。ライセンスは`ui/repository-generated/LICENSE-ELK.md`に保持する。画面のDADSの部品・トークンは引き続き共用する。

## 対応範囲と不足

Composeのサービス定義と、Python・Rust・JavaScript/TypeScript・HTMLの限られた記述に対応する。FastAPI・Flask・Express、UIの生成、ファイル・SQL・一部AWS SDK等の構文を読む静的な試作である。すべてのフレームワーク、動的な接続先、別リポジトリの構成、本番の配備状態を復元する機能ではない。

TerraformやCDK等は読取候補に含むが、そのリソース・ネットワーク・接続の一般的な抽出は未対応。本文を読んだことと、構成へ意味を対応づけられたことを分ける。Composeが複数ある場合は一つを選び、選んだファイルを画面に示す。overrideの合成、profilesの実際の選択、環境変数の展開は行わない。

箱をまとめる枠は役割の分類であり、サーバーやネットワークの物理的な配置を示すものではない。HTTP要求とAPIの対応など、推定した関係は選択時に説明する。読み取りが増えれば図も変わりうる。疑問の出所は保持するが、過去の図そのものの再表示は未実装。

AI対話による疑問整理、任意アプリの自動準備・計測、実参加者による理解の評価は未完了。[設計と完了条件](system-architecture-design.md)の全項目を、今回の自動試験だけで達成済みにはしない。

# 理解とテストの入口

2026-10-07に本人が指定した二つの機能を扱う。理解機能では公開GitHubのコードを読み取り、構成・入口・関数・参照先をたどる。テスト機能では対象の処理を実行して期待する動作・失敗・未確認事項を確かめる。両機能の間でコードと結果を対応づける。

## 現在の起動方法

PR #110は未マージ。作業ブランチで起動する。

```bash
git switch test/reject-age-151-issue-109
git pull --ff-only
cargo run -- explore
```

表示されたURLを開く。理解だけを使う場合は事例の初期化が不要。GitHubの読取は利用者のブラウザから公開APIとraw.githubusercontent.comへ行う。トークンや非公開リポジトリには対応していない。

理解とテストの記録を同じ画面から使う場合は以下で起動する。

```bash
# 未作成の事例を始めるときだけ実行する。
cargo run -- case init cases/pr110-review
cargo run -- review cases/pr110-review
```

`/`が理解画面。`/review`がテストと判断の記録。事例を作成済みなら初期化は省く。既存の試験や判断は書き換えない。

## 理解画面でできること

1. 公開リポジトリのURLを入力する。任意でブランチ・タグ・コミットを指定する。
2. コミットを固定してファイル構成を取得する。README・設定・コードの最大24ファイルを初回に読む。
3. 作者の説明と読む入口を確認する。説明から同じコミットのGitHubへ戻れる。
4. ファイルを選び、関数宣言と参照先をたどる。行番号付きコードと参照宣言の出所を確認する。
5. 初回に読まなかったファイルは選択時に追加で読む。サイズ上限は1ファイル128KiB。
6. 読取記録をJSONで保存し、同じ画面で開ける。保存記録を開いたことと現在のGitHubとの照合を区別する。

READMEやコメントは作者による説明。入口の候補と簡易解析した参照宣言はコードを読む補助であり、実行順序や実際に通った経路の証明ではない。

## 理解からテストへ

事例を開いている場合は「このコードから確認事項を作る」を使う。固定したコミット・ファイル・行のURLを条件の出所へ渡す。利用者が確かめたい動作を記入する。追加した条件は判定方法未定義なのでUnknownのまま始める。

条件の出所から同じコードへ戻れる。GitHubからコードを読んだだけで任意のアプリを起動することはない。現在の画面から実行できるものは既存の保存デモ。外部アプリには実行設定・観測方法・判定規則が別途必要。

## 解析の範囲

Rust、JavaScript / TypeScript、Pythonの関数宣言の一部を抽出する。JSの相対import、Rustのmodと一部のuse、Pythonの相対fromを既知のファイルへ解決する。複雑な構文、動的import、呼び出しの完全な解析、依存パッケージ内部の解析には対応しない。

コメントや文字列内の関数名を宣言として数えない確認がある。Rustのraw文字列など未対応の構文も残る。解決できなかった参照を「参照がない」と表示しない。未読・取得失敗・一覧の途中切れを表示する。

AIによる業務上の意味の説明・質問への応答は未実装。今回の簡易解析だけで理解機能全体が完成したとは扱わない。任意の公開アプリの自動テスト、非公開GitHubの認証、実環境・実参加者での確認も残る。

## 読むコードと確認方法

- `ui/scanner.js`：公開URL、版の固定、範囲を限定した読取、宣言・参照の抽出。
- `ui/explorer.js`：説明とコードの行の表示、参照先への移動、読取記録、確認事項への引継ぎ。
- `src/review.rs`：理解とテストの二画面をlocalhostで配信する。
- `tools/scanner-tests.mjs`：コメント・文字列・Rustのライフタイム、版固定、相対参照、URLと上限、API制限。
- `tools/explorer-smoke.mjs`：固定したGitHub応答を使うブラウザ操作と出所の引継ぎ。実参加者の理解評価ではない。

GitHubのTree APIの仕様は[公式資料](https://docs.github.com/en/rest/git/trees)を参照した。公開コードは認証なしで取得できる。一覧がtruncatedの場合は全体を取得したとは扱わない。

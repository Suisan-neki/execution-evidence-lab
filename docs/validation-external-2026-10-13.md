## 公開GitHubの固定版へ接続した結果

本リポジトリの公開済み`acf5e930d1883edb53bca51cfa30dbde2b356d7e`、64ファイルを対象にした。起動ファイルは`examples/observable-store/app.mjs`、入力は合成JSON、観測名は`stored_matches_input`、対象は`record-1`。

ローカルGitに取得済みの固定版からコピーして実行し、保存物の読み出し・入力との照合を対象コードが報告した。判定はSatisfied、観測1件。続いて`repo prepare`で新しいディレクトリへ同じ公開コミットを取得し、checkout・対象コードの実行を行わずに取得完了を記録した。その取得先からコピーして実行する一往復も条件を満たす判定となった。

Gitは親環境の全変数を引き継がず、取得に必要なプロキシ・証明書設定だけを使用する。対象アプリにはこれらを渡さない。初回はネットワーク設定まで消したためDNS取得に失敗した。必要な設定をGitだけへ渡して修正した。

途中で試したblobの遅延取得は、1ファイルごとの取得待ちが増えたため採用しなかった。現在は対象コミットの浅い履歴をまとめて取得する。遅い試行の終了までに事例が更新されたケースでは、試行を残し、古い版からの取り込みを拒否した。既存の事例や判断を上書きした結果ではない。

これは実在する公開コードの接続確認。合成の入力・条件であり、実医療データ・運用担当・稼働AWS・iOSの試験ではない。対象コードの報告と独立した状態の確認も別に扱う。

## 隔離方式と残る限界

作業環境ではbubblewrapのnamespace起動が拒否された。起動後の終了コード1、観測なし、Unknownを残し、local方式へ切り替えない動作を確認した。Linuxの隔離が成功した証拠としては扱わない。CIの条件付きテストも、利用できた場合の成功と、利用不能時の停止を分けている。

## 引き継ぎ後の再現確認（10月13日）

PR #126の`46049d9`から新しくcloneして確認した。Rustのfmt・check・44テスト・clippy・build、コード読取の試験と比較13事例は成功した。

`npm run test:external`は、親の`evaluations/`がまだないと`ENOENT`で停止した。CIでは先に比較試験が親を作るため、この条件を確認できていなかった。再現スクリプトで親だけを作り、試行の出力先は新規作成に限定する修正を加えた。CIでも外部試験を比較試験より先に実行する。

未作成の親とその下の出力先を指定して、コード改修・再確認待ち・判断時の根拠・再試験・四つの観測条件・前後比較・共有資料の出力が成功した。同じ出力先の再指定は`EEXIST`で停止し、既存の試行を再利用しない。修正後の`npm run test:external`も成功した。

今回の変更は出力先の準備とCIの順序だけで、画面やRustの実行処理は変更していない。既存の画面試験は上記CIの結果を参照する。

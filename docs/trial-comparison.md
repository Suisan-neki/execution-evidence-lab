# 二つの試行を画面で比較する

同じ確認事項に二つ以上の試行を取り込むと、「二つの試行を比較する」が表示される。比較元と比較先を選び、観測時の判定・理由・根拠・未確認事項を並べて読む。コード・入力・引数・条件・環境・宣言した依存先の値も比較する。関連：#131・#123・#78・#79。

## 確認する順番

1. 確認事項の「二つの試行を比較する」を開く。初めて開いたときは、直近の二つの取り込みを選んでいる。
2. 比較元と比較先を選び、「選んだ二つを比較」を押す。同じ試行の組合せは受け付けない。選択だけでは時間順序を推定しない。
3. 二つの「観測時の判定」と理由を確認する。「現在の条件に対応する記録か」は別に表示する。古い成功を現在の不足に代えて使わない。現在の判定は最新の試行と未回答事項を含め、確認事項の先頭で確認する。
4. 「違いと不足する記録」を読む。例えば同じコードで失敗用の引数から正常用の引数へ変えた場合は、引数と起動コマンドの差がある。コード改修、入力、観測対象を同時に変えた場合はそれぞれ表示する。記録の値が同じ項目も開ける。
5. 根拠へのリンクで、選んだ試行の出来事・観測へ移動する。取り込み当時の参照コードと実行記録の固定版へ戻れる。参照行に実際に到達したことは、このリンクだけでは証明しない。
6. 必要なら比較をJSONで保存する。事例の識別子と版、選んだ試行、判定と適用範囲、比較した値、限界を残す。比較や保存は事例の版・試行・判断を変更しない。

選択を変えると前の比較を消す。同じ画面で最新版を読み直した場合は選択を保持し、現在の条件への適用範囲を読み直した事例から更新する。画面全体を開き直すと、直近の二つの取り込みを選び直す。

## 比較の範囲

画面に読み込んだ取り込み記録と、サーバーが計算した観測時の判定を使う。対象ディレクトリや答え合わせ用の保存物を画面から追加で読み込まない。固定版の外部実行、保存デモ、固定版アダプターの記録に対応する。複数の確認事項に同じ試行を取り込んでも、それぞれの条件の中で比較する。

記録がない項目は「比較を確定できない」とし、記録が不足している理由を表示する。`null`が指定された入力と、入力の記録がない状態も区別する。JSONオブジェクトはキー順だけの差を変更にしない。配列の順序は比較する。試行ごとの識別子、開始時刻、前の試行への参照は構成の違いの件数に含めない。試行識別子は二つの観測欄に表示する。

画面で正確に表せない大きな整数を含む項目は、比較を確定できない理由を表示する。JSONの読取時点で値が丸められている可能性があるため、その項目の同一性や正確な値は元の保存記録で確認する。ダウンロードした比較資料には、確定できない状態と理由も残す。

実行時のGit tree・ランタイム・方式と、起動・入力・観測の設定を比較する。アダプターでは固定版、対象ファイルのblob、アダプターのコード、ランタイム、故障条件、確認範囲を比較する。独立した実行経路、実際の外部状態、記録していない依存先を推測で補わない。

結果が変わったことだけでコード改修の効果を特定しない。比較した値が同じでも、記録外の依存先や実環境が同じとは保証しない。医療業務での有効性、利用者の理解、因果推定は別に評価する。

## 読むコード

`ui/trial-comparison.js`が同じ条件の二つの取り込みを検査し、値の差と不足、観測時の判定、現在の適用範囲を返す。判定規則は既存の`src/workspace.rs`を使い、このJavaScriptでは再計算しない。`ui/review.js`が選択・比較・根拠とコードへの移動・JSON保存を扱う。`src/review.rs`で比較モジュールを配信する。

反例は`tools/trial-comparison-tests.mjs`。画面の失敗→再試験、版・入力・観測対象の変更→判定不能、比較と保存、選択の保持、根拠とコードへの移動は`tools/external-smoke.mjs`で確認する。合成データを用いた操作確認と実参加者の評価を区別する。

# 11月の汎用版と医療特化版の進め方

2026-10-07の本人の希望は、11月に一度汎用版を完成させ、利用者を増やしながら医療特化版を並行して作ること。未踏に採択された場合も、両方を続けながら全体を更新する。この資料の完成条件と分割方法は実装側の案であり、11月の公開や採択を確約するものではない。

## 汎用版の完成条件の案

最初はローカルで持ち込んだシステムを確認する版を対象とする。利用者が自分の条件を記入し、実行記録との対応、観測不足、条件変更後の再確認、人の判断と改修・再試行を追える状態を目指す。公開形態は未決定。

| 範囲 | 現在 | 11月までに必要な作業 |
| --- | --- | --- |
| 事例と利用条件 | 空の汎用事例を作成可能。条件・出所・質問を記録できる | 初回利用の手順、一般的な題材での操作説明と試用 |
| 外部システムの記録 | captureでstdout・stderr・終了を記録。終了だけで条件を判定しない | 医療固有の構造を要求しない観測入力と判定規則の追加方法、別アプリでの接続例 |
| 条件・根拠・更新 | 版と宣言した依存先の照合、再確認の理由、判断時の根拠を保存 | 変更漏れ・依存先の宣言漏れの扱い、入力・記録形式の版管理 |
| 共同レビュー | 同じ端末で役割と判断理由を記録できる | 初めて使う人が一件を進める手順、記録のバックアップ・取り出し |
| 比較と限界 | 13事例の確認手順を再現。合成の反例を含む | 別事例、実利用者による理解・負担の確認、導入手順の改善 |
| 配布 | Rustソースとローカル起動手順 | 対応OS、ライセンス、配布物、更新方法を決めて確認する |

汎用版が完成したという記録は、上の必要項目と確認結果を照合してから残す。現時点では完成済みではない。外部共有・認証・権限を備えたWebサービスは追加の範囲であり、現在のlocalhost画面をそのまま公開しない。

## 共通部分と医療特化の分け方

事例、条件、出所、版、根拠、更新履歴、人の判断、比較出力は共通部分として維持する。一般の条件文に医療業務の要件を埋め込まない。医療特化では、実際の運用担当から得た閲覧・保存・失敗対応の条件、認証と権限、対象アプリの観測方法を追加する。

今はVitalSensingの固定版の規則と対象情報がworkspace.rs内にある。汎用の観測入力を追加する際は、これをアダプターの実装へ分け、共通の事例・履歴の形式を両方で利用する。今回の空の事例作成は入口の準備であり、アダプターの完全な分離や任意の業務条件の自動判定はまだ実装していない。

## 作業順の案

1. 10月は汎用の外部観測入力、一般的な題材の一往復、初回利用の説明と配布方法を進める。医療実環境の情報待ちを、この作業の開始条件にしない。
2. 11月は上の完成条件を確認して汎用版を一度配布し、使った人の記録から説明・接続・再確認の負担を修正する。試用者の確保が必要な部分は別に追う。
3. 医療特化は実要件と試験環境が得られた範囲から並行する。現在の模擬索引を実保存・実閲覧の証明にしない。
4. 未踏に採択された場合も共通部分の更新を双方へ反映する。採択前は、今回の単純な規則で十分な部分と、比較で不足が分かった部分を区別して次の技術課題を決める。

学会・地方版未踏の予定と評価目標は[ロードマップ](roadmap.md)で引き続き追う。汎用版の完成、医療業務での有効性、研究の新規性は別の到達点として記録する。

# MONAIで学習から結果の読み出しまでを試す

## 実装前に選んだ試作条件

2026-10-17、親Issue #138の代表ワークフローとして次を選んだ。医療機関から確認した要件や、モデルの性能評価の基準ではない。

- 固定版MONAI 1.6.1のソース、torch 2.8.0+cpu、numpy 2.3.3、Python 3.12.12のLinux amd64コンテナを使う。既存の依存11件の配布ファイルをそのまま使い、追加のデータセットを取得しない。
- seedを144に固定し、MONAIで64×64の合成画像とラベルを作る。ファイルへの保存・読取、強度の正規化、float32のtensorへの変換を通す。
- MONAIの2次元UNet、channels=(4,8)、stride=2、入力・出力各1channelを使う。Adam、学習率0.001、DiceLossで3回だけ重みを更新する。有限の損失と、重みの変化を確認する。損失の減少や精度を完成条件にはしない。
- 重みと処理設定をチェックポイントへ保存し、新しいモデルへ再読込する。推論はMONAIのsliding_window_inferenceを、画像全体を含む64×64の一つの窓で行う。窓を分けたときの接合の正しさはこの試験では扱わない。
- チェックポイントの前後で重みのハッシュを照合する。再読込後の推論を、保存前のモデルによる推論に対し、全画素で絶対許容差1e-6・相対許容差1e-5で照合する。結果をnpyに保存し、別のPythonプロセスで再読込して同じ許容差で照合する。
- 入力欠損、チェックポイント破損、保存先がディレクトリである異常、1回の更新後のSIGKILLを試す。復旧後には新しい正常な試行を作り、依存・入力・重み・出力を比較する。

各段階を未観測・実行中・成功・失敗として記録する。途中で失敗した後の段階を失敗に読み替えない。強制中断時には最後の段階を実行中のまま残し、その段階の完了を確認したとはしない。

## 実行する

DockerとNode 24.19.0を用意した新しい作業コピーで実行する。依存導入と固定版の手順は[固定した環境の手順](pinned-environments.md)を参照。

```bash
cargo build --locked
node tools/environment-smoke.mjs monai-cpu
./target/debug/execution-evidence-lab environment inspect examples/monai-workflow/recipe.json
node tools/monai-workflow-smoke.mjs
cargo run -- review evaluations/ci-monai-workflow/case
```

`environment-smoke`は固定コミットの取得と、既存の合成推論の確認を行う。`monai-workflow-smoke`は同じ依存の設定で6回の新しい試行を行う。設定とスクリプトは実行前に表示し、試行のplan.jsonにも残す。既存の出力先は再利用しない。

| 試行 | 実際に行う異常・操作 | 記録で確認すること |
| --- | --- | --- |
| normal | 正常な一連の処理 | 10段階の成功、3回の更新、重み・推論・保存後の照合 |
| input-missing | 保存した入力ファイルを削除する | 入力読取の失敗。学習以降は未観測 |
| checkpoint-corrupt | 保存後のチェックポイントを不正なバイト列に変える | torch.loadの失敗。推論以降は未観測 |
| save-is-directory | checkpoint.ptというディレクトリを作る | チェックポイント保存の失敗。再読込以降は未観測 |
| interrupted | 1回目の更新後、対象プロセスをSIGKILLで止める | 学習の完了は未観測。親が得た終了コードは-9で、チェックポイントは作られない |
| retry | 正常な設定に戻して新しい試行を作る | 依存の版・ハッシュと、入力・前処理・重み・出力のハッシュをnormalと比較 |

SIGKILLは試験用スクリプトが決めた時点で自分へ送る。任意の実アプリを外部から中断して回収する一般的な機能ではない。保存失敗もディレクトリとの衝突であり、ディスクの故障や容量不足の再現ではない。

## 記録と判定の出所

各試行は`evaluations/ci-monai-workflow/<試行名>/runs/run-.../`に残る。environment.jsonは依存準備・対象コマンド・終了の記録、result/workflow.jsonは対象内で書いた段階の記録である。入力、ラベル、参照出力、チェックポイント、推論結果、別プロセスの読取結果も残す。基盤側の確認用スクリプトが、残った生成物のバイト数とハッシュを読み直す。

段階の記録は、成功・失敗を明示した段階だけを報告観測として事例へ取り込む。実行中・未観測の段階には成功や失敗の観測を作らない。試行の新しい報告で観測が欠けた場合に、古い正常時の成功へ戻らないことも確認する。

取り込み用traceのcompletedは、回収した内容の報告が完了したことを表す。対象の学習・推論の完了とは分ける。中断した対象のworkflow.jsonはcompleted=falseのままで、学習完了の観測は作らない。対象が中断していても、その前に完了した段階の報告は残る。

条件にはMONAIの固定コミットを対応づけ、段階の報告にはこのリポジトリの試験用スクリプトの固定コード参照を残す。実行環境・依存・スクリプト・モデルと処理設定はtrace.context、各試行の記録への参照とハッシュは個々の観測のdetailに記載する。事例の表示は報告された範囲の判定であり、実行経路を独立して証明したという表示にはしない。

正常と再試験の比較はdependency-comparison.jsonとcase-comparison.jsonに残す。新しい試行の成功で過去の失敗・未観測や、判断の根拠を書き換えない。

## 確認範囲

ローカルではPython・JavaScriptの構文、設定と補助ファイルのハッシュを確認する。この開発環境にはDockerがないため、実際のCPU処理と故障・再試験・事例への取り込みは`MONAI synthetic workflow`のCIで確認し、成否と記録をPRに残す。CIの合成データ・チェックポイント・記録は7日間保管する。

MONAI自身の版の表示は、タグ情報のないアーカイブで0+unknownになる場合がある。その値を上書きせず、固定コミットでソースの版を照合する。今回保存するのは推論用の重みと処理設定で、optimizerの状態を含む学習再開用のチェックポイントではない。複数画像での学習、窓を分ける推論、医療上の性能、実参加者との評価は未確認。

読む順番はrecipe.json、workflow.py、readback.py、tools/monai-workflow-smoke.mjs、事例の10条件と各試行のworkflow.json。設定・段階の処理・別プロセスの読取・報告への変換の順に確認できる。

# 最初の要件：正常時の1件送信

このファイルは正常時の1件送信に必要な要件を整理する。Codexが案を提示し、本人がPRをレビューして採用・修正を判断する。未決定事項を提案で埋める場合は「提案中」と明記し、本人の承認を推測しない。

## 合意済みの範囲

- 小さな再現用アプリを実行対象にする。
- 架空のテスト用データ1件を送信する流れを扱う。
- 最初は正常時を動かし、その後に初期実験仕様の3種類の異常条件を加える。
- 操作・表示と、観測できた出来事を結びつけた根拠を示す。
- 観測した記録とは別経路で、実際に保存されたデータを確認し、評価に使う。
- 未確認事項を、確認済みの事実と区別する。

## 設計とレビューで決めること

最初に全部を埋める必要はない。今回のPRに関係する項目から整理する。成功表示の意味や保存の扱いなど、期待する結果を左右する未決定事項は実装前に確認する。

## PRで確認する観点

次の問いは、要件と実装の対応をレビューする観点として使う。本人へのクイズや段階の通過判定を、実装開始の必須条件にはしない。

1. アプリで「送信成功」と表示するとき、どの処理がどこまで完了したことを利用者へ知らせるか。その意味を選ぶ理由と、コード上の条件は対応しているか。
2. 画面に「送信成功」と表示され、基盤は受信の記録を取得できたが、保存に関する記録を取得できなかった。この記録だけで何を言えて、何をまだ言えないか。追加で何を確認する必要があるか。

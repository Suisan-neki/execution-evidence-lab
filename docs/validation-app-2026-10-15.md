## 画面の操作で確かめたこと（`npm run test:app`）

`tools/app-smoke.mjs` が、試験用の一時ディレクトリにデータの保存先を作ってサーバーを起動し、ブラウザーで画面を操作する。既存の `cases/` と `data/` は使わない。

| 2. 理解する | 目的・起動・構成・処理の流れを、根拠の種類とコードの参照付きで表示した。キーボードで手順を切り替え、フォーカスの枠が表示された |
| 3. 調べる | 「保存できなかったらどうなる？」から、`TaskDict.write` の `raise BadFile` と、`_main` の `except BadFile` を示した。244行目を選んで関数を調べた |

## 検証中に見つけて直したこと

- 解析しない種類のファイル（cobraの `.go` など）を、読んでいないファイルとして数えていなかった。「66件のうち4件を読んだ。読み取っていないファイルは0件」と表示していた。理由付きで未読として示すように直した。
- 別のリポジトリを開いても、前のリポジトリのコードを表示したままだった。開くたびにコードの表示を閉じるように直した。
- 40文字のコミットが折り返されず、幅390pxで横にはみ出していた。文字200%では手順の名前が隠れ、通知の見出しが細く折り返されていた。
- 実行環境がないときに、理由は表示するが実行のボタンを押せた。
- GitHub Actionsで、Actionsのトークンを「内容を確認してください」として拒否した。2026年10月2日からトークンは500文字前後の形式（[GitHubの告知](https://github.blog/changelog/2026-10-02-stateless-github-app-installation-tokens-rolled-out/)）になったが、256文字までに制限していた。中身を解釈せず、空白・改行のない4096文字以内なら受け付けるように直した。

## 確かめていないこと

- 実際の運用担当・開発者による操作と理解。読み上げソフト、色の対比の測定、Windows・iOSなどほかの環境。
- bubblewrap方式とネットワークの遮断。この環境では使えなかった。
- 依存パッケージを持つ対象、Python・Node.js以外の言語の実行、複数の利用者による同時編集。
- AIの接続先が実際に応答する場合の説明の質。今回はAIを設定しない状態と、接続に失敗する状態だけを確かめた。

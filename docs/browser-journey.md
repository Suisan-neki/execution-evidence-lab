# ブラウザで順に進める

最初の起動だけをターミナルで行う。

```bash
cargo run -- app data/app --port 8765
```

表示されたURLを開く。以後はブラウザで操作する。既存の保存先を使えば条件・試行・モードの履歴を引き継ぐ。

## デモで流れを確かめる

1. 「デモを始める」を選ぶ。送信→受信→保存→応答の説明を読む。
2. 「次へ：試す内容を選ぶ」で通常保存・保存失敗・記録の欠落・通信断から一つ選ぶ。
3. 次の画面で何を実行するか確認し、自己申告の記入者を入力する。「試験を始める」を押したときだけTCP送受信と保存を1回実行する。
4. 結果画面で各段階の取得記録・現在の判定・未確認事項を読む。「別の状況で試す」で比較する。
5. 「対象を選ぶ画面に戻る」で元の事例へ戻る。

デモの条件と履歴は`data/app/demo-case`へ保存する。元の事例は`data/app/case`で、互いのモードや結果を書き換えない。デモのモードはデモ画面で選ぶ。実在する人の情報は入力しない。これは同梱する保存デモの操作で、呼び出し番号表示の自動再現は[別の開発者向け手順](modes-and-queue.md)に残す。

## 自分のソフトウェアを調べる

1. URLと任意の版を入力して「読み込む」。コードを読むだけで、対象は起動しない。
2. 目的と主な構成を確認する。読取範囲・起動方法・詳しい処理は必要なときに開く。
3. 「期待する動作を確認する」で名前と役割を入力し、確かめたい動作を書く。保存後はその期待だけを確認する画面へ進む。
4. 「実装と確認方法を対応づける」でコードと確認方法を記録する。人の確認・質問・食い違いは別の欄を開いて残す。
5. 「この期待を試す」から起動と入力→試す状況→判定の条件へ進む。任意の依存先・コンテナなどは必要な場合だけ開く。
6. 実行前の画面で対象コミット・入力・観測・実行方式を確認する。「試験を始める」を押すと起動する。
7. 結果の画面で現在の判定と最新の根拠を確認する。過去の試行・再試験・判断は必要なときに開く。

ブラウザの戻る・進むを使える。再読込すると固定コミットと保存済みの条件を読み直す。保存していない試験の入力は初期案へ戻り、実行前の確認から再読込した場合も設定へ戻る。移動や再読込だけで試験を始めない。

## モードと補助操作

画面上部の確認モードで汎用／医療を選ぶ。変更が保存されると完了を表示し、失敗した場合は保存済みの選択へ戻す。入力する確認候補が変わるが、過去の条件・判定・履歴や実行権限は変わらない。切り替えは本人確認なしのブラウザ操作として記録する。

「確認項目・変更履歴・共有資料」には候補の追加、説明の詳しさ、変更理由を指定したモード記録、JSONとHTMLの出力を置く。「構成図から確認する」では従来の図・質問・個別観測を使える。local／bubblewrapの実行方式はサーバー起動時に指定する。

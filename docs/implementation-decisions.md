# 今回の実装で選んだこと

2026年10月6日の実装期間。ここに記すのはCodexが試作を進めるために選んだ仕様と理由であり、採用済みの医療業務の要件ではない。

| 選択 | 理由 | 確認した範囲と残ること |
| --- | --- | --- |
| CLI、localhostのTCP | 操作から保存・表示までを実際に動かせる | GUI、端末と遠隔サーバーは未再現 |
| 長さ付きJSON、64KiB上限 | 分割されたTCP読み出しでも終端を決め、過大な受信サイズを拒否する | 書き出し前のJSON直列化には入力分のメモリを使う |
| I/Oと接続待ち各1000ms | 実験が無期限に待たない | 高負荷環境では正常処理も待機上限に達しうる |
| 試行ごとのcreate_newとsync_all | 過去の記録を上書きせず、ファイル書き込み成功を限定して扱う | ディレクトリ同期、原子的更新、電源断復旧は未保証。DBではない |
| 試行・データ・送信試行のID | 時刻の近さで関連を推測しない | 1件・1送信限定。再送、複数端末、分散時計は未対応 |
| MutexでJSONL記録を直列化 | 同時の書き込みで行を混ぜない | 計測は処理時間へ影響する。非計測時との負担比較は#50で未実施 |
| 通信断用TCPゲート | 要求を実際に受け、サーバーへ渡さず切断する | OSレベルのパケット損失ではない |
| 保存開始前の人工失敗 | 受信済みと保存成功を分けて確かめる | 実ディスク障害・部分書き込みの再現ではない |
| 保存の観測のみを省く | 保存失敗と観測不足を分ける | ログ基盤全体の欠落・再接続は未再現 |
| 判定器にTruthを渡さない | 答え合わせの情報を観測の代わりに使わない | 参加者評価用のCLIではTruthを見せない手順が必要 |
| 出来事の番号・順序を検査 | 壊れたJSON、重複・欠番、時間の逆転を黙って採用しない | 書き換えられたログの真正性を保証する署名はない |
| 条件の変更はUnknown | 意味が変わった条件へ古い規則を当てない | 対応する判定規則を増やす仕組みは今後必要 |
| ソース指紋をビルド時に付ける | src、build.rs、Cargo.toml、Cargo.lockの変更を識別する | FNV-1aは暗号学的検証ではない。外部対象、SDKの実体、OS全設定は含まない |
| compareで差分を示す | 過去の結果と現在の実行条件を区別する | 設定一致は将来の保証ではない。captureは対象コード未識別のため証拠一致を常にfalseにする |
| 外部プロセスの出力をファイルへ流す | 大量出力をメモリにためず、子孫が持つパイプによる待機を避ける | ディスク消費上限・隔離・外部状態の初期化・子孫の停止は未対応 |
| 固定版ハンドラーの依存先を注入 | 元の処理を動かしつつAWS資源を使わず一経路を試す | 実S3、DynamoDB、Cognito、iOS、管理画面は別に確認する |

異常終了などで記録出力を完了できなければcomplete.jsonは作られない。途中のファイルを残し、成功した試行として扱わない。

次の確認の選択は少数の明示的な規則による試作で、学習済みの質問選択や新規アルゴリズムではない。#65・#93の文献比較と、#86・#87の比較評価へ接続する。

ソース指紋にUIとアダプター・固定情報も含めた。指紋は変更の識別用であり、暗号学的な署名ではない。アダプターの固定版照合も、稼働環境の真正性を保証しない。

## 理解とテストの入口の修正

本人の2026-10-07の指定に合わせ、GitHubを読む理解画面とテスト結果を記録する画面を分けた。保存試験の記録画面から始まっていた入口を修正する。

公開APIとraw.githubusercontent.comは利用者のブラウザから読む。GitHubのトークンや取得コードをサーバーへ送らない。コミットを固定して出所の行へ戻る。対象コードをスキャンだけで実行しない。

最初の読解は簡易な宣言・参照の抽出と作者の説明の表示。静的な参照関係を実際の実行経路としない。未知の構文や未読ファイルがあるため完全な理解とは扱わない。コードを条件の出所へ渡しても試験方法は未定義として始める。

以下は今回より前に進めたテスト基盤の選択。

- 共通比較入力からdecisions.basisの自動判定理由・行動提案を除く。元の事例と判断履歴は変えず、人が記入した判断・理由は双方の資料へ同じように渡す。説明を外す表示へ説明が混入する問題を避けるため。
- 通常の確認手順の参照実装をNode.jsで別に作り、同じinput.jsonから限定した保存条件を再現する。13事例の一致は規則の再現確認であり、優位性や人の作業時間の検証ではない。
- 発行前の索引成功と対象不明の失敗をUnknownにする。成功を使う前に対象と順序を照合する必要があるため。実ハンドラーの新しい障害を発見した意味ではない。
- 空の汎用事例は既存Workspaceを再利用する。条件・質問・回答を自動で作らず、医療特化の要件待ちでも一般の事例を開始できる。アダプター完全分離は次の作業。
- 画面の再描画時は未保存の入力と選択を保持する。未編集の条件文・規則・依存先は最新版へ更新する。ページ終了後の下書きの永続化は含めない。

コミットが違えば同じ本文でも参照先更新後は再確認する。未宣言の依存先まで同じと判断できないため。確認したファイルだけに限定する適用範囲の推定は、今後の研究・実装で比較する。医療機関の採用済み要件や新規性を確定した意味ではない。

## 10月13日の固定版の実行・汎用観測

- Gitのコミットから通常ファイルをコピーして、未コミットの作業ファイルを実行しない。origin・コミット・起動ファイル・参照ファイル・行範囲を照合する。symlink・submoduleは扱わない。
- Node.jsとPythonを明示し、依存パッケージは自動で導入しない。JSON入力・引数・観測名・対象を試験設定に保存する。資格情報を含む親の環境変数を引き継がず、試行用の環境変数だけを渡す。Pythonのbytecodeキャッシュが固定版へ作られないようにする。
- 対象コードの観測を共通のJSONLで受ける。識別子・順序・参照先・行を照合し、欠落、別試行、食い違いから成功を補わない。観測の呼び出し元はプロセスの申告で、独立した実行トレースではない。
- 条件ごとの依存先へ試験設定・ランタイム・入力・方式を保存する。違う条件の試験設定を全体の共通値として混ぜない。事例の変更と試行の取り込みは競合を検査し、実行中の変更は上書きしない。
- localは自分で確認したコードの接続用。OSの隔離、子孫プロセス全体の停止、外部状態の復元は保証しない。Linuxのbubblewrapはnamespace・読み取り専用の固定版・試行用workを使い、起動不能時にlocalへ切り替えない。
- 次の確認は明示的な規則で選ぶ。実行・終了失敗は起動設定と標準エラーの確認、固定版の変化や無効な観測は出所の照合、正常終了後の観測欠落は選択した観測名・対象の出力箇所の確認へつなぐ。未回答の利用条件と古い根拠はそれぞれ質問・再試験を優先する。新規性や最適な質問選択を示した意味ではない。

仕様・制限は[pinned-execution.md](pinned-execution.md)。本人の仕様採用、実運用の条件、実参加者の理解、比較での優位性は未確認。

## 画面からの固定版実行（10月13日、#128）

- 起動時に一つのGitリポジトリと方式を指定した場合だけ、画面から固定版を実行する。通常のレビュー画面から任意のファイル・コマンド・取得先を指定する操作は追加しない。
- 一件を別スレッドで実行し、HTTPの閲覧を処理できる状態にする。同じサーバーの二重起動をMutexで拒否する。複数サーバー全体の排他や実行の中断・再開は含まない。
- 受付、起動直前、結果取り込み時に事例の版を照合する。途中の変更では試行を残し、現在の事例を上書きしない。終了・取り込み完了と、業務条件の成功を区別する。
- 完了状態を読んでから事例を読み直す。古い事例の判定を取り込み完了の結果として見せないため。編集中の入力は既存の下書き保持を使う。
- 実行ボタンと設定の保存は同じ入力検査を使う。方式・リポジトリパスは起動時の設定を使い、ブラウザからの上書きを受け付けない。localはOSの隔離ではない。

これは接続操作の試作で、任意アプリの自動計測、医療業務の要件採用、研究の有効性を示すものではない。

## 読み込みの別名と呼び出し元（#129）

- 読み込み宣言のローカル名と参照先の名前を記録し、候補の宣言と対応づける。未読ファイルに仮の関数を作らない。参照先を追加で読むと、同じ固定版の解析を更新する。
- 型や動的な束縛を解決しないため、呼び出し先・元は常に候補として示す。引数や簡単な局所宣言に同名の記述があれば、対応づけを保留する。複雑なスコープの完全な検査ではない。
- 呼び出し元の探索は最大400関数、表示は最大80件にする。未読のコードと上限を表示し、結果がないことを呼び出しがない証明にしない。
- 同じ解析モデルの関数範囲と案内を再利用する。追加読取・版更新でモデルを作り直すため、旧版の対応を新しい版へ流用しない。
- Pythonの拡張子省略を同名のJavaScriptファイルへ解決する反例を修正し、言語ごとの参照先候補を使う。再export・パッケージ内部・動的呼び出しは未対応。

## 汎用バックエンドv1（#133）

- 医療固有の固定対象の検査と模擬索引の判定を`src/adapters/vitalsensing.rs`へ分離し、既存の保存・固定版実行・医療アダプターの判定を維持する。
- 外部からの観測を`reported_assertion`として追加する。基盤による固定版実行とは別の型にし、報告者・出所・構成を保存する。順序・識別子・条件の版と参照先を照合し、欠落・未完了・食い違いはUnknownにする。
- APIはlocalhostの`/api/v1`とし、トークンを新規の所有者専用ファイルへ保存する。ブラウザのOriginがある場合は同一Originを要求し、OriginのないCLIはトークンを要求する。従来の画面向けAPIは維持する。
- Rust側の比較は保存した生のJSON値を比較し、整数の精度をJavaScriptへ依存させない。サーバーとCLIで同じ判定・比較を使う。
- バックアップは全版の記録と判断当時の根拠を検査し、新しいディレクトリへ復元する。途中の復元はマーカーで未完了と分かるようにし、既存を置き換えない。作業領域や答え合わせ用のファイルは別に管理する。
- コード読取・静的解析は既存のJavaScriptモジュールを埋め込み、信頼するNode.js処理からJSONで呼ぶ。対象リポジトリのコードを起動しない。30秒の待機上限と入出力の上限を設ける。
- HTTPは最大16件を別スレッドで扱い、途中のリクエストやネットワーク読取でほかの閲覧を止めない。事例への書き込みは従来の排他と版照合を使う。

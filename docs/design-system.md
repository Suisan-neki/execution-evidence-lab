# デジタル庁デザインシステムの適用

更新日：2026年10月14日。理解と試験の画面（`ui/app.html`、`ui/app.css`、`ui/app.js`）で使った資料・版・部品と、確かめた範囲を記録する。

## 使った資料と版

| 資料 | 版 | 置き場所 |
| --- | --- | --- |
| [デザインシステム](https://design.digital.go.jp/dads/) の色・文字・余白のトークン | npm `@digital-go-jp/design-tokens` 2.0.1（パッケージのsha256 `e8a8cd5c…7038c`、`dist/tokens.css` のsha256 `9fac82ee…5d88`） | `ui/dads/tokens.css` |
| HTML版のコンポーネント例 [design-system-example-components-html](https://github.com/digital-go-jp/design-system-example-components-html) | コミット `af8b6656c8d864a22ef444d088e5568f3416f6aa`（2026年9月9日） | `ui/dads/components.css` |

どちらもMITライセンス（著作権者はデジタル庁）で、ライセンス文を `ui/dads/LICENSE-*` に置いた。`components.css` は `src/global.css`（`:root` のトークン定義を除く）と、使う部品のCSSを順に連結したもので、内容は変更していない。

サーバーはCSPで外部のスタイルを読み込まないため、3つのCSSを画面のHTMLに埋め込んで返す。Webフォントは読み込まず、トークンの `--font-family-sans` に指定された書体のうち、端末にあるものを使う。

## 使った部品

| 部品 | 画面での使い方 |
| --- | --- |
| ボタン（`dads-button`、solid-fill・outline・text、lg・md・sm） | 読み込む、調べる、この動作を確かめる、この内容で試す、比べるなど |
| 入力欄（`dads-input-text`）、複数行の入力欄（`dads-textarea`）、セレクトボックス（`dads-select`） | URL、質問、期待、引数、判定の条件、判断 |
| ラベルと補足（`dads-form-control-label`、必須の表示） | すべての入力欄。補足は `aria-describedby` で入力欄に結ぶ |
| ラジオボタン（`dads-radio`） | 故障の種類 |
| 通知バナー（`dads-notification-banner`、standard、error・warning・info-1） | 操作の失敗、取得できなかったファイル、実行が未対応の言語、AIの失敗、再試験の案内 |
| ステップナビゲーション（`dads-step-navigation`） | 4つの手順。現在の手順に `aria-current="step"` を付ける。横並びで名前が入りきらない幅・文字の大きさでは、縦並び（`data-orientation="vertical"`）に切り替える |
| ディスクロージャー（`dads-disclosure`） | 未読のファイル、ファイル一覧、関数、技術的な詳細など、必要なときに開く情報 |
| テーブル（`dads-table`） | 判定の条件ごとの期待と観測、二つの試行の比較 |
| 文字の大きさのユーティリティ（`dads-u-std-24B-150` など）、視覚的に隠すユーティリティ（`dads-u-visually-hidden`） | 見出し、ステップの番号の読み上げ |

通知バナーのアイコンは、部品のCSSが求める位置に置く簡単な図形を `ui/app.js` で描いた。デザインシステムのアイコン素材ではない。

## 状態を色だけで伝えない

- 判定は「○ 条件を満たす」「× 条件を満たさない」「？ 判定できない」と文字で表示する。枠の色と線の種類（判定できないときは破線）は補助に使う。
- 観測の結果も「○ 期待どおり」「× 期待と異なる」「？ 観測できていない」と文字で示す。
- 根拠の種類は「コードで確認」「作者の説明」「解析の推測」「AIの説明」と文字で示す。
- 通知バナーの見出しは「エラー:」「注意:」「お知らせ:」で始める。

## 確かめた範囲

`tools/app-smoke.mjs`（Playwright、Chromium）で次を確かめた。結果は[検証記録](validation-app-2026-10-15.md)にある。

- Tabキーで最初に「本文へ移動」へ移り、キーボードで手順の切り替えとボタンの操作ができる。フォーカスした要素に枠線が表示される。
- 入力欄のラベルで操作対象を取得できる（ラベルと入力欄が結ばれている）。URLの形の誤りは、入力欄の下に文字で示し、`aria-invalid` を付ける。
- 幅390pxと幅320px（幅1280pxの画面を400%に拡大したときの幅に当たる）、文字の大きさ200%（幅1280px）のそれぞれで、4つの手順の画面が横にはみ出さず、通知の見出しが細く折り返されず、手順の名前が隠れない。画面写真も目視で確かめた。
- 文字の大きさは、ルート要素の `font-size` を200%にして確かめた。ブラウザーの拡大機能や、ブラウザーの文字サイズ設定そのものは使っていない。

画面の読み上げソフトでの操作、色の対比の測定、Windowsなどほかの環境での表示は確かめていない。

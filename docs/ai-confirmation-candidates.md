# AIの説明から確認事項を作る

公開GitHubの固定版について質問したとき、設定済みのAI接続先にコード抜粋を送り、説明と確認候補を得る。利用者が候補の根拠と未確認事項を読み、期待を編集して保存し、既存の試験設定へ進むための試作。AIが試験を実行したり、結果・安全性・人の合意を判定したりする機能ではない。

## 操作

1. [理解と試験の画面](understand-and-test.md)を起動し、公開リポジトリの版を固定して読む。
2. 「コードに質問する」で質問を書き、「AIの説明も求める」を押す。接続設定がない場合はこの操作を表示しない。
3. 「次に確かめる候補」で期待・理由・根拠の行・分からないことを読む。根拠が今回の抜粋にそろわない候補は取り込めない。
4. 「この候補を編集する」を押す。期待の下書きがある場合は上書きせず、先に保存するか内容を消すよう案内する。
5. 自分の利用条件に合わせて期待を書き直し、記入者を入力して保存する。この段階では未試験で、人の確認は追加しない。
6. コードとの対応づけと確認方法を記録し、「この期待を試す」で設定を確認する。対象の取得・実行は従来と同じ明示操作で行う。

候補を表示しただけ、または編集画面へ移っただけでは、事例・試行を保存しない。下書きはブラウザの現在のページにだけあり、再読み込みで失われる。保存した条件・提案は通常の事例履歴に残り、再読み込みでも読み出せる。

## 根拠と保存

`src/ai_response.rs`がAIのJSONを型と件数・文字数の上限で検査する。型の異なる応答や、モデルが`verified`などの照合結果を指定した応答は拒否する。説明だけの従来形式も受け付ける。

参照は二段階で照合する。固定コミットの読取記録に行が存在することと、今回実際にAIへ渡した抜粋に全行が含まれることを分ける。候補の全参照が両方を満たした場合だけ編集操作を表示する。行の存在は意味の正しさを保証しない。

保存時の条件は`manual_only`、発言の種類は`proposal`にする。条件と提案の`origin`に、AI由来であること、保存した記入者、モデル名、質問、対象の版、元の候補・理由・参照・未確認事項、送った抜粋と応答本文のSHA-256を残す。候補の原文と保存した期待の文を区別できる。全体のJSON・HTML出力と全版バックアップには従来の出所として含まれる。

出所は12KiB以内で保存できる候補だけを取り込む。上限を超えたときに未確認事項を切り捨てず、質問を絞って問い合わせ直すよう案内する。ハッシュは内容の識別用で、AI事業者による署名や説明の正しさの証明ではない。

## 確認範囲と残る評価

ローカルの合成応答を使い、実際のRust APIとAI通信の経路を検証する。実在しない参照、抜粋外の行、根拠なし、形式の誤りを成功に置き換えない。AIへの問い合わせ自体で事例を変更しないことも確かめる。実際のモデルへの有料呼び出しはこの確認には含めない。

実モデルが適切な確認事項を提案できるか、手作業・静的解析・汎用AIへの直接の質問に比べて理解や次の行動が改善するか、費用と所要時間が許容されるかは未評価。利用者の業務条件、本人の理解、医療上の妥当性をモデル応答から補わない。実参加者による試用は別に必要。

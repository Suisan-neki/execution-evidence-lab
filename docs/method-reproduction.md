# 確認手順の再現と判定規則の反例

PR #110、Issue #121・#86・#118の継続。2026-10-07に、実環境や参加者を必要としない範囲を追加した。

```bash
cargo build --locked
node tools/reproduce-methods.mjs
# 保存先を指定する場合は、新しいディレクトリを使う。
node tools/reproduce-methods.mjs evaluations/methods-new
```

各事例の実TCP試行、事例の版、比較資料、共通入力と識別値、結果一覧を出力する。反例のログは元の試行を書き換えずsynthetic-traceへ複製して加工する。実際に発生した障害の観測として数えない。results.jsonには実TCPと合成加工の区別を残す。元の保存物・truth.jsonは比較方法の入力に含めない。

## 比較する方法

| 方法 | 確認方法 | この実行から言える範囲 |
| --- | --- | --- |
| 今回の試作 | Rustの条件版・宣言値・識別子・出所・成功と失敗の照合 | 現在の規則の出力 |
| 通常のチェックリストの参照実装 | 同じinput.jsonからNode.jsの別実装で未回答、条件版、依存先、識別子、出所と記録を照合 | 限定した保存条件を通常の手順でも再現できること |
| 単純なラベル検索 | 成功・失敗の出来事名だけを検索 | 識別子や出所等を確認しない方法の限界。有力な比較相手ではない |

参照実装はworkspace.viewの結果、生成した判定理由、人の判断時のbasis、答え合わせを使わない。期待値と参照手順は開発側が定めたもので、独立した評価者の基準ではない。人による対話・コード読解の全作業を機械化した意味ではなく、goat/YAGI等の研究手法の再現でもない。

case exportはbaseline.md、checklist.md、linked.md、without-links.mdを出力する。全資料の元情報をそろえる。共通入力の人の判断は行動・理由等だけを含め、basisの自動説明を除く。判断当時のbasisは元の事例に残す。without-linksにも元の宣言した対応は含めるので、これは表示の比較であり、関係の情報そのものを消す実験ではない。

## 再現した13事例

正常、保存前の人工失敗、受信前の遮断、保存観測の欠落、別の送信試行、異なる出所の成功、成功と失敗の食い違い、コードの宣言値変更、条件版変更、未回答の追加、後の閲覧という別条件、未宣言の依存先変更、判断履歴がある場合を照合する。

この13事例では、今回の試作とチェックリストの参照実装の結果は一致した。単純なラベル検索は、別試行、出所、食い違い、条件変更等で誤った成功を返す。この差だけを今回の方式の優位性としない。未知事例の発見能力、人の確認時間・理解・安心感は未評価。

## 修正した規則と残る失敗

固定版アダプターの契約試験では、対象キーの発行より前の成功記録を旧規則が成立として扱えた。修正後は、発行前の更新と、対象キーがない失敗記録をUnknownとして照合を提案する。元の実ハンドラーでは正常・人工失敗・観測欠落の出力が変わらないことを別に確認する。

依存先は宣言されたものだけを照合する。未宣言の依存先を変更しても保存条件は成立のままで、変更の影響を検出できない事例を残した。また、同じ識別子を持つ虚偽のログの真正性や、宣言値と実環境の対応は確認できない。履歴の保存だけでこれらを解決したとは扱わない。

実環境との照合、別の実事例、有力な既存構成と同じ作業予算の実測比較、実参加者は引き続き保留する。既知事例の回帰試験と研究上の比較評価を分けて記録する。
